# MJ承認と自動合流の手順

根拠：frontend issue 18のMJ承認コメント6466715276（2026-10-28）。追記根拠：同IssueのMJコメント6469750567（2026-10-28 22:04「C」）。承認範囲と安全確認の合否を分けて扱います。

1. 通常確認と安全確認を既存のscripts/review-pr.shに渡し、同じheadのPASSと試験の成功を確認します。未完了や未解決指摘は合格にしません。確認は3回まで。合否が出なかった回は数えず、既存の待ち時間・代替モデルの決まりに従います。
2. CODEOWNERSと両確認役が、患者情報の新しいAI/外部送信、鍵・権限・ログイン・WAF、本番への配備、AIを縛る決まり（AGENTS.md・CLAUDE.md・確認役の合格基準・GitHubの自動の作業・CODEOWNERS）に当たるか確認します。場所が一覧外でも内容が当たればMJへ承認を頼みます。
3. 新しい画面は合成データの画像をfrontend issue 18に掲載します。何を・なぜ・推奨・その結果を日本語で書き、チャットのKIPPを通じてMJの返事を待ちます。写真を用意できない時は未確認として止めます。
4. 上記に該当しないPRは、両確認と試験に合格したら、該当しない理由をPRに1行記録し自動合流します。GitHubの保護規則が承認を要求する場合は規則を変えずに待ちます。
5. 本番配備とアプリ配信はMJが決め、各リリース手順に従います。合流の許可から配備の許可を推定しません。

安全・個人情報一般、既存画面の文言、内部構造、依存、文書という分類だけではMJ承認対象にしません。内容で上記に当たる場合と、MJが明示的に判断を指定した場合は承認を待ちます。

CODEOWNERSは呼出・送信・認証・権限・秘密・WAF・本番配備に加え、AIを縛る決まりを保護します。AGENTS.md・CLAUDE.md・/.github/全体・**/*review*rules*・**/*review*policy*はMJの承認対象です。 公開の約束を保つため、NURVISのプライバシーページ /peaceful-corporate/app/**/nurvis/privacy/ も保護します。 業務データ一般という分類だけでは丸ごと所有対象にしません。
この追記は各リポジトリに追加PRを1本ずつ作り、CODEOWNERS・AGENTS・この手順書を同時にMJが1回承認します。費用上限、利用枠、同時実行数、道具の許可、確認回数、GitHub rulesetは変更しません。
